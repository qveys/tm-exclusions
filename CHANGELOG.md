# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

### Fixes

- **An unwritable configuration directory is reported, not hidden behind a success notice**: with a read-only `$HOME` (or a `~/.config` that is a file), the first-run helper printed `Created default custom config` although nothing was written, and leaked the shell's raw `No such file or directory` (untranslated). It now reports `Could not create the default custom config:` (new `MSG_CONFIG_CREATE_FAILED`, en/fr) and the run continues on the built-in catalog; `--init` exits 1 with the same message instead of a raw `mkdir` error. `write_custom_config_if_absent` returns 2 when the file could not be written. Covered by `tests/test_home_edge_cases.sh`.
- **A newline in a directory name no longer sends a relative path to `tmutil`**: the scan reads `find` output line by line, so `$HOME/x<NL>b/node_modules` reached the classifier as `$HOME/x` and `b/node_modules`; the second line, a path relative to the current directory, was matched, checked and (outside `--dry-run`) excluded against whatever `b/node_modules` the cwd held. Only paths under the scan root are now classified. Directories whose own path contains a newline are therefore not discovered (a known limit, as before — they never worked). Covered by `tests/test_home_edge_cases.sh`.
- **A `$HOME` containing `&` no longer corrupts the catalog on Bash 5.2+**: the loader expands `$HOME` with `${var//\$HOME/$HOME}`, and since Bash 5.2 an unquoted `&` in that replacement stands for the matched text (`patsub_replacement`), so `/Users/R&D` turned every rule into `/Users/R$HOMED/...` and silently excluded nothing. The option is now switched off at startup (ignored by Bash 3.2 and 4.x). Covered by `tests/test_home_edge_cases.sh`.
- Accept `--lang=en` and `--lang=fr`, and allow language flags after the three `--add` operands.
- Reject `--force` without `--uninstall` and the combination of `--uninstall` with `--report-only` before scanning.
- `--add` rejects empty targets and directory patterns containing `/` before appending a rule.
- **Hugging Face and Claude VM exclusions only take regenerable data**: `~/.cache/huggingface` was excluded as a whole, taking the login token and user `assets` out of backups; only `hub/` and `xet/` ship now. `Library/Application Support/Claude/vm_bundles` is narrowed to `claudevm.bundle/rootfs.img`, so `sessiondata.img` stays backed up (a `keep` rule is documented for the whole image). Exclusions left by an older catalog on the two former parents are dropped by the retired-parent migration.
- **JetBrains `Toolbox/plugins` is no longer excluded**: the `JetBrains/*/plugins` glob also matched JetBrains Toolbox's own `plugins` directory, which holds the user's installed plugin payloads and their state. The rule now lists the versioned IDE folders (`IntelliJIdea2024.*`, `IdeaIC2024.*`, `PyCharm2024.*`, …), so IDE plugin caches stay excluded and Toolbox keeps its data; an exclusion left on `Toolbox/plugins` is dropped by the migration. Other versioned folders the old glob covered (Fleet, …) keep their existing exclusion, which loses nothing.
- **Read-only status checks never call `sudo`**: `tmutil isexcluded` is now read unprivileged, so `--dry-run` and `--report-only` never escalate; an unreadable status is still an error (exit 2), never silently "included". The privileged check moved to the add/remove branches of `process_path()`, where a mutation outside `$HOME` needs it, and the retired-parent migration relies on the same read.
- **One error per failed scan traversal** instead of one per configured pattern, with `find`'s first filesystem diagnostic attached; partial results are kept.
- **`Pods` and `.output` patterns only match real project directories**: both names are generic. `Pods` is now excluded only next to a `Podfile` or `Podfile.lock`, `.output` only when it holds the Nitro build marker `nitro.json`. Directories excluded by an earlier run are not re-included by apply; `--uninstall` still removes them, or use `tmutil removeexclusion <path>`.
- **The report no longer runs `tmutil listexclusions`**: that verb does not exist (`tmutil` only knows `addexclusion`, `removeexclusion` and `isexcluded`), so the call exited 64 and the report section always read `status: failed (exit 64)` on a real Mac. The section, its `MSG_REPORT_TMLIST_*` strings and the `--dry-run` read-only lookup of that verb are removed; the per-path status lines are unchanged and `--dry-run` only calls `isexcluded`. Covered by `tests/test_end_banner.sh`, `tests/test_safety.sh` and `tests/smoke.bats-like.sh`.
- **The `.gradle` pattern no longer excludes the Gradle user home**: `pattern|.gradle` matched `~/.gradle` itself, taking `gradle.properties` (signing credentials, tokens) and `init.d` scripts out of backups, although the static rules deliberately target only `caches/` and `wrapper/`. A `.gradle` directory is now excluded only next to `build.gradle(.kts)`, `settings.gradle(.kts)` or `gradlew`. `~/.gradle` itself is never matched, even when `$HOME` holds one of these files. A `~/.gradle` exclusion left by an earlier run is dropped on the next apply or `--uninstall` (`--dry-run` reports it); apply leaves it alone when you exclude `~/.gradle` yourself with a `path` rule, and a `keep` rule below a retired path (for example `keep|$HOME/.gradle/gradle.properties`) no longer blocks the removal — this also fixes the same case for the retired CoreSimulator parent.
- **`venv` and `virtualenv` patterns only match real environments**: these names also belong to source trees (CPython's `Lib/venv`, the `virtualenv` package, the oh-my-zsh `virtualenv` plugin). A match now needs `pyvenv.cfg` or `bin/activate` inside it. Look-alike directories (and non-project `.gradle` directories) excluded by an earlier run are not re-included by apply, which cannot tell them from exclusions you set yourself: `--uninstall` still removes them, or use `tmutil removeexclusion <path>`.
- **No temporary file left by a signal between `mktemp` and its registration** ([#92](https://github.com/qveys/tm-exclusions/issues/92)): a SIGINT/SIGTERM/SIGHUP arriving after `mktemp` created a file but before `register_tmp_file` recorded it left a `tm_exc_*` file in `TMPDIR`. All temporary files (`kept`, `all`, `scan`, `sorted`, `disk` and the space journal) are now created through one helper, `make_tmp_file`, inside a single private work directory made once by `mktemp -d` (`ensure_tmp_dir`); around that one `mktemp -d` `INT`/`TERM`/`HUP` are switched atomically from `on_signal` to a recorder (the `mktemp` child ignores them), then the previous handlers are restored and a signal received meanwhile is replayed to them (cleanup, exit `128+n`), so no signal is lost and there is no window without a handler. The directory is removed with everything in it by the cleanup, only by its exact `tm_exc_work.XXXXXX` path; `TMPDIR` is resolved once to its physical path (a symbolic link retargeted while `mktemp` runs no longer leaves the directory behind and no longer makes the run fail); a `TMPDIR` containing a newline or other control character falls back to `/tmp` (the work path used to be split at the newline, so the cleanup could recursively remove another existing directory). Works under Bash 3.2 and 5. Covered by `tests/test_tmp_signal.sh` (`make test`, `make lint`), which suspends `mktemp` right after it created its entry, sends SIGTERM, SIGINT and SIGHUP and checks the exit status (143/130/129) and the absence of any `tm_exc_*`, and which proves that a decoy directory survives a `TMPDIR` containing a newline.

### Performance

- **Multi-layer scan pruning** ([#13](https://github.com/qveys/tm-exclusions/issues/13)): the dynamic scan no longer only filters after discovery; its single `find` now stops descending where the post-filters would drop everything below anyway — (1) configured `prune` zones (`-path <zone> -print -prune`, all modes), (2) existing static `path` exclusions not blocked by a `keep` (`-path <path> -prune`, not in `--uninstall`), (3) below a directory already matched by a pattern without a match guard (`-name <p> -print -prune`; not in `--uninstall`, off when any `keep` rule exists, never for the guarded `target`, `worktrees`, `site-packages` patterns). The excluded paths are identical to the full traversal (same `tmutil` calls, same order — apply, `--uninstall` and `keep` scenarios) and the post-filters stay as a safety net. Visible change: a prune zone now yields one `Pruning (skipping scan of):` entry / `Pruned:` count / report `SKIP` line per zone root instead of one per nested match, since the nested matches are no longer visited. On the generated tree of `scripts/measure-scan.sh` (4 933 directories) the scan evaluates 108 instead of 2 933 directories and runs in ~1.2 s instead of ~11 s with Bash 3.2. `TM_EXCLUSIONS_NO_SCAN_PRUNE=1` restores the full traversal (measurements, rollback). Documented in `docs/ARCHITECTURE.md` ("Scan pruning layers"); covered by `tests/test_scan_pruning.sh` (parity, visited-directory assertions, guard-list sync) and `scripts/measure-scan.sh` (`make test`, `make lint`). `tests/test_scan_single_find.sh` keeps its raw-discovery equality check on the full traversal (`TM_EXCLUSIONS_NO_SCAN_PRUNE=1`) and now also asserts the pruned traversal never discovers a match outside the per-pattern reference.
- **Single-pass dynamic scan** ([#50](https://github.com/qveys/tm-exclusions/issues/50)): `scan_dynamic_patterns()` now walks `$HOME` with one consolidated `find` — `find "$HOME" -maxdepth 6 -type d \( -name p1 -o -name p2 … \)` — instead of one full traversal per configured pattern, cutting repeated tree walks and I/O on large home directories. Each discovered directory is still tagged with every matching pattern, so results, ordering and post-filters (`pattern_match_allowed`, prune zones, kept-prefix pruning) are unchanged; no `-prune` is used, so nested matches (e.g. `node_modules/.pnpm/*/node_modules`, needed in uninstall mode) are still discovered. Covered by `tests/test_scan_single_find.sh` (`make test`), which compares the single pass against a per-pattern reference and counts `find` invocations (1 instead of N).

### Features

- **XDG package caches** ship by default next to their `~/.` counterparts: npm (`~/.cache/npm/_cacache`, `~/.cache/npm/_npx`), pnpm (`~/.local/share/pnpm/store`) and Gradle (`~/.local/share/gradle/caches`, `~/.local/share/gradle/wrapper`). All are regenerable downloads.
- **Photos libraries are skipped during discovery**: `*.photoslibrary` directories are pruned in every mode (apply and `--uninstall`), like iCloud `Mobile Documents`, so a large library is no longer walked for pattern matches.
- **Catalog: Homebrew Caskroom** — `/opt/homebrew/Caskroom` and `/usr/local/Caskroom` (cask payloads and install receipts, reinstallable with `brew reinstall --cask`) ship by default next to the `Cellar` rules. Like the Cellar, they hold the only copy of CLI-only casks (e.g. `op` from `1password-cli`): after a restore, `brew reinstall --cask <name>` brings them back. The report's inventory still lists installed casks.
- **Catalog: regenerable subtrees that were neither scanned nor excluded**: `~/.bun`, `~/.nvm` and `~/.local/share/uv` are prune zones whose reason said `handled by static rules`, but those static rules are opt-in, so nothing under them was excluded. The focused, regenerable parts now ship by default (`~/.bun/install/cache`, `~/.nvm/versions/node/*/{lib,bin}` — not `etc/npmrc`, which may hold an auth token —, `~/.nvm/.cache`, `~/.local/share/uv/python`, `~/.local/share/uv/tools`); the mixed roots stay opt-in and the prune reasons say what is really covered.
- **Catalog: new default rules** — `~/.cache/uv`, `~/.cache/puppeteer`, `~/Library/pnpm/store` (pnpm's default store on macOS; `~/.pnpm-store` is the legacy location), `/opt/homebrew/Cellar` (Apple Silicon twin of `/usr/local/Cellar`), VS Code caches under `~/Library/Application Support/Code` (same five directories as Cursor), and a new **Android** category (`~/Library/Android/sdk`, `~/.android/cache`; `~/.android/avd` is opt-in).
- **Optional two-pane tmux interface (`--tmux`)** ([#14](https://github.com/qveys/tm-exclusions/issues/14)): an interactive run can now display in a dedicated tmux session with two panes — the left pane is the normal progress/status view, the right pane follows the debug log (the same `log_info` lines written to FD 5 through `TM_EXCLUSIONS_DEBUG_FIFO`). The wrapper starts its own tmux server on a private socket path inside the run's work directory (`tmux -S TMP_DIR/s`, checked in bytes against the 104-byte unix-socket limit), so it never touches an existing session and no other server can already own that name; it re-execs the script with the original arguments (minus `--tmux`) in the left pane, so the scan, exclusions and exit code are unchanged and nothing is scanned twice. `--tmux` only activates on an interactive TTY: with `--quiet` or redirected stdout it is ignored and the run behaves exactly as without the flag; if `tmux` is missing, or the log file/`new-session` cannot be created, a stderr notice appears and the run falls back to normal (one scan, same exit status). From the moment the session exists there is no fallback: a failed log pane is reported and the run continues in one pane (the log is a regular file followed by `tail -f`, so a missing or closed pane never blocks the scan on a full pipe), and losing the client stops the run with status 1 rather than scanning again. The log pane is created with `split-window -d`, so it never takes the keyboard and a `sudo` password stays in the left pane. Config/help commands (`--help`, `--init`, `--add`, `--list`, `--edit`) never launch it. The client runs in the background on an explicit tty while the script `wait`s for it, so a signal interrupts that wait: cleanup (also on EXIT/INT/TERM/HUP) stops the client and kills only this run's session, server and socket immediately, instead of after the user detaches. The wrapper publishes the inner status once, as soon as the scan ends (so a detach at the closing prompt returns it instead of waiting for a second client) or with 130/143/129 when a signal arrives first; the status file is the guard (temporary file + rename, so a signal cannot leave it empty or half-written), it can never be overwritten, and the signal the parent sends while closing is ignored from the first statement of the handler, and the left pane is supervised from its creation (a signal that kills it before its traps are installed still closes the session and publishes its exit status). Script path and arguments are `%q`-quoted for the same bash; every other path travels through the session environment, so spaces and special characters are safe and there is no shell-injection surface. Rollback: revert the PR. Covered by `tests/test_tmux_ui.sh` (`make test`, `make lint`) with a stub tmux (two-pane wiring, single scan, exit-code propagation, `split-window` failure without a second scan, cleanup, SIGTERM while attached) plus an opt-in real-tmux check on a dedicated socket; the PTY-based interactive cases run on the Linux CI too (the helper uses `python3`), while Bash 3.2 and the real-tmux integration are only exercised locally.
- **Interactive end-of-run summary banner with space excluded** ([#44](https://github.com/qveys/tm-exclusions/issues/44)): the final summary of an interactive run (stdout is a terminal) is now a banner showing the counters (newly excluded, already excluded, skipped, **missing paths**, errors, blocked), the cumulative **space excluded** by the run in readable units (`KB`/`MB`/`GB`/`TB`, from the sizes already measured — no extra `du` walk, nested paths counted once), the saved report path and a copy-pasteable `tmutil isexcluded <shell-quoted first path>` verification tip (a placeholder-free example when no path was processed). `--dry-run` labels the figure *simulated*: no exclusion is added or removed (no `addexclusion`/`removeexclusion`); the read-only status lookups (`isexcluded`, `listexclusions`) still run; `--report-only` labels it *space needing exclusion* unless `--dry-run` is also set (the simulated label then wins); sizes that could not be read — or only partially measured because `du` exited non-zero on unreadable children, on GNU and BSD alike — yield `≥ <total> (partial, unmeasured paths: N)` (lower bound truncated, never rounded up; a readable path under a partially readable parent still contributes, nested paths never counted twice) or `unknown` when nothing usable was measured, never a false total; paths whose name contains a newline are counted as unmeasured without running `du`, and tabs in names no longer break the size cache, and a name ending in a newline (e.g. a link `small<LF>`) is no longer mistaken for its neighbour `small` — including through an alias, a chain of links or a relative link to such a target (decided in the size computation only by `size_path_unsafe()`; `normalize_path` and the keep/exclusion guards are unchanged). `--quiet` never prints the banner and its stdout gains no line (the space line stays in the saved report; it only benefits from the boundary size-formatting fix). The same `Space excluded:` line is added to the saved report and to the counters of non-quiet plain output, unless `TM_EXCLUSIONS_SKIP_DU=1` or in uninstall mode. Visible changes: the interactive banner gained the missing-paths counter, and the report path line is now part of the banner instead of a separate `Report saved to:` line (non-interactive non-quiet output only gains the `Space excluded:` counter line; `--quiet` output gains no line). Sizes just below a unit boundary no longer print `1024.0M` (`1048575K` → `1.0G`). The figure is the sum of the sizes of the tracked paths minus overlap by path prefix (ASCII case folded, so `Cache` then `cache/Child` on case-insensitive APFS count once; the folding assumes the default case-insensitive macOS volumes: on a case-sensitive volume, two rules targeting two paths that differ only by case are counted as one — an undercount), aggregated in one `sort`/`awk` pass (6000 paths in well under a second). It does not detect aliases or hard links between different paths (a link and its target, or two hard links to one file, are separate measurements), in apply mode the order of application can change the displayed lower bound for a path that inherits its parent's exclusion, and it assumes a stable directory tree during the run; it is a display value only, no exclusion, `keep` or uninstall decision depends on it. Detailed per-path lines stay available with `--verbose` and in the report. Covered by `tests/test_end_banner.sh` (`make test`, `make lint`).
- **Inventory — command-line tools across PATH** ([#49](https://github.com/qveys/tm-exclusions/issues/49)): the inventory now surveys the executables installed in every `$PATH` directory, in the interactive output, the verbose output and the saved report. Standard system directories (`/bin`, `/sbin`, `/usr/bin`, `/usr/sbin`) are only counted (`[sys] /usr/bin (120 binaries — omitted)`); every other directory is treated as a toolchain one and gets its count plus all tool names (`[dev] /opt/homebrew/bin (312 binaries):`), wrapped like the Homebrew lists. Empty, relative, missing and duplicate PATH entries are ignored (first occurrence order kept); symbolic-link tools (Homebrew) count, non-executables, broken links and directory links do not; names with spaces or newlines are safe. Each directory is read in a single shell pass (no `find`/`ls`, no fork per file). Skipped by `TM_EXCLUSIONS_SKIP_INVENTORY=1` and by `--quiet`; the existing `PATH: N existing directories` line is kept. `TM_EXCLUSIONS_SYSTEM_PATHS` (colon-separated) overrides the system directory list, mainly for tests. Covered by `tests/test_path_inventory.sh` (`make test`) on a fake PATH.
- **Inventory — installed applications with disk sizes** ([#47](https://github.com/qveys/tm-exclusions/issues/47)): the inventory now lists every `.app` bundle found in `/Applications` and `~/Applications` (up to two levels deep, so `Utilities/Foo.app` is included and nested helper apps are not) with a readable `du -sh -H` size (symbolic-link apps such as `Safari.app` are listed and measured as their target; broken links are ignored), in the interactive inventory, the verbose output and the saved report. Sizes come from a single grouped `du` call; names with spaces or even newlines are handled (NUL-separated end to end), an unreadable bundle shows `-`, and missing or empty folders print a localized notice. `TM_EXCLUSIONS_SKIP_INVENTORY=1` skips it. The `/Applications (top-level)` count is kept. Covered by `tests/test_apps_inventory.sh` (`make test`) on a fake HOME, fake app tree and fake `du`.
- **Inventory**: installed Homebrew casks and CLI formulae are now listed by name in column-wrapped blocks (terminal width, no trailing commas), both in interactive output and in the saved report; a friendly notice is shown when `brew` is not installed, and `TM_EXCLUSIONS_SKIP_INVENTORY=1` still skips the block. ([#48](https://github.com/qveys/tm-exclusions/issues/48))
- **VM and disk image discovery** (`scan_images=true`): also detects hypervisor bundles `.utm`, `.vmwarevm`, `.parallels` and `.pvm` (any size, contents pruned; a `keep` inside a bundle protects the whole bundle, its disks are not excluded individually), `.iso`/`.ova` files over 512 MiB, and VirtualBox `.vbox` files (the whole folder only when it is named after the file, never `$HOME`). `Library/CloudStorage` is pruned like iCloud `Mobile Documents`. The 50-candidate cap and 512 MiB gate are unchanged, but duplicates and candidates under another candidate (unless protected by `keep`) are dropped before the cap; in `--uninstall` there is no such reduction, a cap of 200 candidates (instead of 50), a `.vbox` offered both as file and as folder and bundle contents are not pruned, so disks excluded individually by older versions are still found; discovered paths keep the `Discovery:` report context. ([#51](https://github.com/qveys/tm-exclusions/issues/51))

### Build

- Faster `make test` on macOS. The tmux fixture wakes its client on session closure, Homebrew smoke tests measure fixture applications, and the locale validator indexes keys once per comparison. Multiple assertions on the same CLI invocation share its captured output.

- **Tests: no more false green from `source <(…)` under Bash 3.2** ([#88](https://github.com/qveys/tm-exclusions/issues/88)): under `/bin/bash` 3.2.57 `source <(command)` returns 0 without defining anything, so a suite loading the CLI that way could run no assertion and still exit 0 (it passes under Bash 5, which hid the defect). `tests/test_safety.sh` and the unit blocks of `tests/smoke.bats-like.sh` now load the script from a temporary file (`write_functions_file` in `tests/test_helpers.sh`, removed with the suite's temporary directory by its existing trap) and check that the expected functions exist (`require_functions`); `test_summary` now fails any suite that ran zero assertions. `tests/test_safety.sh` used to crash under Bash 3.2 at `normalize_path` after 124 assertions; it now runs all 141. Covered by `tests/test_loader_guard.sh` (`make test`, `make lint`), which also fails if a `source <(…)` or `. <(…)` reappears in `tests/` (its own file included), `scripts/` or the Makefile, written on one line, with `--`, or continued with a backslash anywhere; it fails closed (`cannot scan <path>`) when a scan target is missing, `find` fails or a file is unreadable; it lists files with `find -print0` and never parses `file:line:text` output, so a checkout path containing `:` is handled.
- **`scripts/add-category.sh`** ([#58](https://github.com/qveys/tm-exclusions/issues/58)): scaffolds a new category in `config/default.conf` from flags (`--name`, repeated `--add TYPE TARGET REASON`) or interactive prompts on a terminal. It refuses empty fields, `|`/control characters/newlines, unknown types and an already existing category or rule (active or opt-in; `~/x` is normalized to `$HOME/x`, trailing slashes dropped), refuses a catalog whose insertion anchors are not recognized, inserts the `#@Name` section following the file layout and bumps `EXPECTED_CATEGORY_COUNT` (the single source of the category count, in `tests/smoke.bats-like.sh`). It validates on a copy of the repository placed next to the checkout (never under `TMPDIR`, which the catalog excludes on macOS) with `check-conf`, `check-i18n`, then `make check` unless `--skip-tests`, and only then overwrites the two real files in place (modes preserved) after a backup, restoring both on any failure or INT/TERM/HUP (otherwise exit 1, nothing written); duplicate detection compares `~/x`, `$HOME/x` and trailing-slash forms on both sides; every added line is re-verified; `verify_added_lines` is unit-tested; a second signal cannot interrupt the restore; the work copy goes under `$HOME` when the checkout is under `TMPDIR`/`/var/folders`; symbolic-link targets are refused; both files are snapshotted under the lock and the install refuses (exit 1, nothing written) if either changed since, so a lost lock can no longer cause a silent lost update; a `.add-category.lock` directory prevents concurrent edits (taken through an `O_EXCL` guard file `.add-category.lock.guard`, because some `mkdir` implementations such as uutils coreutils report success when the directory already exists); end of input at a prompt aborts. `--dry-run` prints the diff only, `--root DIR` targets another checkout. Category names are not localized, so no locale key is written. README and ARCHITECTURE no longer quote the category count. Covered by `tests/test_add_category.sh` (`make test`, `make lint`) on a temporary copy of the repository.
- **`pre-commit` hook** ([#60](https://github.com/qveys/tm-exclusions/issues/60)): `.githooks/pre-commit`, activated by `make setup`, checks only the files staged for the commit — ShellCheck on `*.sh` (same options as `make lint`; `bash -n` on `locales/*.sh`), `scripts/check-conf.sh` on `*.conf` — and blocks the commit on errors. Staging a locale file without its sibling prints a non-blocking reminder to run `make check-i18n`. A missing `shellcheck` only warns. The **staged content** is checked (blobs exported from the index to a temporary directory; sourced files resolve from the working tree), so a partially staged file is judged on what will be committed. NUL-safe file handling (spaces/newlines in names), works from any subdirectory and in linked worktrees; skip once with `git commit --no-verify`. The automatic `make` bootstrap now reports on stderr when it replaces a different local `core.hooksPath` (global config untouched, silent when already `.githooks`) and can be skipped with `TM_EXCLUSIONS_NO_HOOKS=1`; any `make` call otherwise re-sets `core.hooksPath`, so `git config --unset core.hooksPath` is not a permanent opt-out (documented in README/CONTRIBUTING). Covered by `tests/test_pre_commit.sh` (`make test`, `make lint`) on throwaway repositories.
- **`make test-summary` / `scripts/test-summary.sh`** ([#59](https://github.com/qveys/tm-exclusions/issues/59)): runs every `tests/*.sh` suite unmodified and prints one compact line — total, passed, failed — followed by only the failed assertions with their output (a suite that crashes without a `FAIL` line is reported with the tail of its output). Failures keep their raw output (multi-line output, context before and after the `FAIL` line, bounded). Exit status is 0 on success, 1 otherwise (also when no suite is found); `make test` / `make check` are unchanged. Covered by `tests/test_summary.sh` (`make test`) on fake passing, failing and crashing suites.
- **`make check-i18n` / `scripts/check-i18n.sh`**: locale parity checker, run as part of `make check`. It compares the `MSG_*` keys of `locales/en.sh` and `locales/fr.sh` and reports, with `file:line`, every key missing from the other locale (exit 1); it exits 0 when the keys are in 1:1 parity. Covered by `tests/test_check_i18n.sh`. ([#56](https://github.com/qveys/tm-exclusions/issues/56))
- **`make check-conf` / `scripts/check-conf.sh`**: standalone syntax validator for `.conf` files, run as part of `make check`. It reports `file:line` errors (exit 1) for unknown types, missing `|` delimiters, empty target or reason, `..` path traversal, typo'd or unsupported `$HOME`/`~` usage, and invalid `setting` keys/values; with no arguments it checks every `config/*.conf`. Covered by `tests/test_check_conf.sh`. ([#57](https://github.com/qveys/tm-exclusions/issues/57))
- **`Formula/tm-exclusions.rb`**: `url`, `sha256` and `version` refreshed to the v1.3.0 tarball. The previous `sha256` did not match the v1.2.0 tarball it pointed at (`93d9f89e…` instead of `956ac268…`), so `brew install --formula ./Formula/tm-exclusions.rb` failed on a checksum mismatch.
- **`.github/workflows/release.yml`**: a missing `HOMEBREW_TOKEN` now fails the release run instead of `exit 0`. The v1.3.0 run was green while the tap was never updated, so `brew install tm-exclusions` kept serving v1.2.0.

### CLI

- **Category sections (`#@Category`)** ([#46](https://github.com/qveys/tm-exclusions/issues/46)): `#@<Category>` lines in `default.conf`, `custom.conf` and `TM_EXCLUSIONS_EXTRA_CONF` now attach the `path`/`pattern`/`keep` rules below them to a category. Non-quiet runs print a `══ Category ══` header per category (also with `-v`, where individual lines are now grouped under their header), and the saved report groups its `Details:` lines under `── Category ──` subheadings. Rules before any marker, after a bare `#@`, or in a config file that defines no section use a localized default category (`Uncategorized` / `Sans catégorie`); each file starts in the default category. Custom `#@MyCategory` sections work in `custom.conf`. Covered by `tests/test_categories.sh` (`make test`).
- **Per-path disk size during exclusion application** ([#45](https://github.com/qveys/tm-exclusions/issues/45)): non-quiet runs now prefix each processed path with its formatted `du -sk` size, right-aligned in a fixed 8-cell column (e.g. `Applying exclusion:     1.0G  ~/Library/Caches`). Missing or unreadable paths show `-` and never fail the run. A cumulative formatted total (`Disk usage total:` / `Usage disque total :`) is added to the end-of-run summary and report counters. Each path is measured once and the report's disk-usage section reuses that measurement (`DU_SIZES`), so trees are never walked twice. `-q`/`--quiet` prints no per-path lines, and `TM_EXCLUSIONS_SKIP_DU=1` disables both the column and the report section.

### Build

- **`make install` / `make uninstall`**: default `PREFIX` is `$(brew --prefix)/bin` when writable, otherwise `/usr/local/bin`. Elevation no longer uses `sudo sh -c` (blocked by restricted sudoers). Cascade: unprivileged `install`/`rm` when the destination is writable, else `sudo /usr/bin/install` (or `/bin/rm`) per file, else a macOS admin dialog via `osascript`.

- `make install` / `make uninstall` also install and remove `locales/*.sh` under `$(SHARE_DIR)/locales/`. ([#16](https://github.com/qveys/tm-exclusions/issues/16))
- **Release flow**: `make release` and `.github/workflows/auto-patch.yml` no longer bump `version` in `Formula/tm-exclusions.rb`. A release's `sha256` only exists after the tag is pushed, so a version-only bump made a local `brew install --formula ./Formula/tm-exclusions.rb` install the *previous* tarball under the new version. The repo formula now stays on the last published tarball (`url`, `sha256`, `version` moving together) and `tests/test_release_logic.sh` fails the build if they drift.
- `make lint` also runs ShellCheck on `tests/test_release_logic.sh` (its `printf` calls now pass colour codes as `%b` arguments, like `tests/smoke.bats-like.sh`).

### i18n

- **External locale files**: all user-visible strings moved out of `tm_exclusions.sh` into `locales/en.sh` and `locales/fr.sh`, sourced at runtime by `load_i18n()`. `resolve_locales_dir()` looks at `TM_EXCLUSIONS_LOCALES_DIR` (ignored as root), the repo checkout, then the installed share dirs; a missing locale file is a fatal error rather than a silent fallback. ([#16](https://github.com/qveys/tm-exclusions/issues/16))
- **`--lang`**: values are allowlisted to `en`/`fr` before any locale path is built, so an untrusted value can never become a sourced filename; unsupported codes report "Unsupported language" instead of "locale files not found".

### Config

- **Report destination in config** (`setting|key|value`): persist `report_path` (saved report file) and/or `desktop_report` (`true`/`false`) in `custom.conf` so unattended runs do not need CLI flags or env vars. Precedence is CLI > environment > config setting > built-in default (`~/.config/tm_exclusions/last_report.txt`). `report_path` is a file path (not a directory), matching `TM_EXCLUSIONS_REPORT`. `#@option` was not used — `#@` lines stay comments reserved for category markers (#34). ([#52](https://github.com/qveys/tm-exclusions/issues/52))
- **Auto-prune `.bak` / `.old` shadow copies**: after config loading, every static `path|<P>` rule automatically extends `CONF_PRUNES` with `<P>.bak` and `<P>.old`. Shadow trees produced by tool reinstalls or migrations (e.g. `.bun.bak`, `.npm.bak`, `.cargo.bak`, `.pnpm-store.bak`) are silently skipped during the dynamic scan without any per-suffix opt-in. `pattern|` and `prune|` catalog entries are not auto-derived. `config/default.conf` is unchanged. ([#25](https://github.com/qveys/tm-exclusions/issues/25))
- **`TM_EXCLUSIONS_EXTRA_CONF`**: opt-in mechanism for power users with large cloud-sync trees. Set the env var to any config file to load it after `default.conf` and `custom.conf`. A missing, non-regular-file (e.g. a directory path), or unreadable value emits a stderr warning and continues — the loader now requires both `-f` (regular file) and `-r` (readable). The example file (`extra-prunes.example.conf`) is installed alongside `default.conf`: in a source checkout under `config/`, via `make install` under `${SHARE_DIR}/` (`$(PREFIX)/../share/tm-exclusions`, i.e. `$(brew --prefix)/share/tm-exclusions/` when the Homebrew bin is writable, otherwise `/usr/local/share/tm-exclusions/`), and via `brew install` under `$(brew --prefix)/share/tm-exclusions/`. `config/default.conf` is unchanged. ([#17](https://github.com/qveys/tm-exclusions/issues/17))

### CLI

- Desktop report policy made explicit: the `~/Desktop` copy is **off by default** (avoids clutter on unattended cron/launchd runs). Opt in with the new `--desktop-report` CLI flag or the existing `TM_EXCLUSIONS_REPORT_DESKTOP=1` env var; both are equivalent. ([#15](https://github.com/qveys/tm-exclusions/issues/15))
- Paths outside `$HOME` use `sudo tmutil addexclusion -p` / `removeexclusion -p` when interactive sudo or a passwordless sudo cache is available; background `sudo -v` refresh for long runs. Non-interactive runs without `sudo -n` **skip** those paths instead of blocking.
- `-h` accepted as an alias for `--help`.
- Config: expand `$HOME` in rule targets (same idea as legacy `default.conf`); optional `#@…` lines remain comments.
- Dynamic scan: narrow `target` and `worktrees` matches to reduce false positives (Rust/Maven/Gradle projects; git/agent worktrees).

### Security / Hardening

- Signal handling and temp file cleanup: register all `mktemp` files and clean them up deterministically on `EXIT`, `INT` (SIGINT), `TERM` (SIGTERM), and `HUP` (SIGHUP), stopping background sudo keepalive and re-raising the signal cleanly.
- `$EDITOR` support with arguments: parse `$EDITOR` into an indexed argument array (`read -r -a`) in `cmd_config_edit` so multi-word commands (e.g. `code --wait`, `subl -w`, `nano -B`) execute properly without invoking `eval`.

### Default rules

- Re-enabled **`path|/private/var/folders`** under macOS Caches. Per-user kernel temp/caches are regenerable; privileged apply uses `sudo tmutil addexclusion -p` when credentials are available. ([#55](https://github.com/qveys/tm-exclusions/issues/55))

The catalog now targets `Caches`, `Temp`, `Volumes`, and `Devices` so root-level simulator metadata stays in backups; comment out `Devices` in a local catalog copy to retain simulator device state. `/Library/Developer/CoreSimulator` is unchanged (system runtimes). Apply / `--dry-run` / `--uninstall` drop the retired parent `tmutil` exclusion when it is still present (manual equivalent: `tmutil removeexclusion "$HOME/Library/Developer/CoreSimulator"`). ([#54](https://github.com/qveys/tm-exclusions/issues/54))

- Default config now ships ~150 rules across 17 categories (up from 39). Path style normalized to `$HOME/...`. New `#@CategoryName` section markers (cosmetic in 1.x; future report grouping tracked in #34). Several entries ship commented (opt-in): `pattern|.cache`, `pattern|site-packages`, `path|$HOME/.docker` (keeps registry credentials). `$HOME/.ollama/models` replaces the parent `$HOME/.ollama` (preserves `id_ed25519` and chat history). Cloud-sync prunes deferred to user opt-in (#44). Parent Application Support roots stay omitted (mix of user data and caches); granular cache subdirs ship enabled (#53). (#37)

### Fixed

- Dynamic scan no longer emits redundant child exclusions under an already-excluded parent. After the parent (e.g. `~/Git/<repo>/node_modules`) is kept, descendants matched by the same or another pattern (e.g. `.pnpm/<pkg>/node_modules`) are silently skipped — they're already covered transitively by the parent. Saves hundreds of lines per pnpm workspace and avoids duplicate `tmutil addexclusion` calls. ([#23](https://github.com/qveys/tm-exclusions/issues/23))
- Report `du -sk` no longer aborts under `set -euo pipefail` when a path has unreadable children (e.g. `/private/var/folders`). `du_size_kb()` captures `du` independently of the formatting pipeline and keeps a partial total when one is printed.
