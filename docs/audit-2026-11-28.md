`origin/master` (`2df767a`, v1.3.0 plus the unreleased changelog). Method: read
the CLI end to end, probe edge cases in a throwaway `HOME` with a stub `tmutil`

## To fix next (small, safe, not done here to keep the change reviewable)

1. **`--add` validation gaps.** `--add pattern '' x` writes `pattern||x`, and
   `--add pattern a/b x` writes a pattern `find -name` can never match. Both are
   silently accepted; `scripts/check-conf.sh` knows the rules, `--add` does not
   reuse them. Effort S.
2. **`--lang` ergonomics.** `--lang=fr` fails with `Unknown argument: --lang=fr`;
   `--add t p r --lang fr` fails with `Argument inconnu : --lang` (a misleading
   message: the flag is valid, its position is not). Accept `--lang=<x>` and
   global flags after `--add`. Effort S.
3. **Silent option conflicts.** `--force` without `--uninstall` is ignored;
   `--uninstall --report-only` keeps the last one. Warn or reject. Unknown
   arguments could also point to `--help`. Effort S.
4. **Catalog candidates** (regenerable caches not covered today; each needs a
   maintainer decision because the catalog is a promise about backups):
   `~/.nuget/packages`, `~/.cache/pre-commit`, `~/.cache/pypoetry`,
   `~/.pub-cache/hosted`, and the `.angular` / `.dart_tool` / `.terraform`
   patterns (the README already uses `.angular` as its `--add` example; a
   `.terraform` directory can hold provider binaries only, but needs a guard to
   stay away from non-project folders). *(read only: not verified on a machine
   holding them.)*

## To discuss

- **`du` dominates the cost of a full run.** See the measurement below. The
  size column and the space banner are the product's selling point, so the
  default stays; options are a `--no-size` flag (today only
  `TM_EXCLUSIONS_SKIP_DU=1`), or a size cap per path.
- **`find` does not use `-xdev`.** A mounted network share inside `$HOME`
  (outside `~/Library`, which is pruned) is walked to depth 6. Stopping at
  filesystem boundaries would be faster and safer, but changes what is
  discovered on machines that keep projects on an external volume linked in
  `$HOME`.
- **Paths containing a newline are never discovered** (they never were; fix 2
  makes that explicit instead of dangerous). Supporting them would mean
  `-print0` and NUL-delimited temp files throughout the scan; not worth it.
- **JetBrains `…/plugins` rules** also drop manually installed (non-marketplace)
  plugins. Reinstallable, but not from the marketplace.
- **`EDITOR` with a quoted path containing spaces** is split on spaces by
  `--edit` (`read -a`). *(read only.)*

## Discarded

- **Quoting every `${var//pat/$HOME}`** instead of fix 1: Bash 3.2 and 5.x treat
  quotes inside the replacement differently; a single `shopt` is simpler and safe.
- **Opt-in catalog entries** (`~/.cargo/bin`, `~/.bun`, `~/.nvm`, Docker, Xcode
  archives…): commented out on purpose, with their reason; not "forgotten".
- **`is_covered_by_kept` is a linear scan per match.** Measured by
  `scripts/measure-scan.sh` (4 933 directories): ~1.2 s with pruning. No
  user-visible cost, not worth a data structure in Bash 3.2.
- **Failing baseline `test_tmux_ui.sh`** (syntax error, line 594): another
  session was editing that file while the baseline ran; not a repository defect.
  The full suite is re-run on the final head (below).

## Measurements

- **Test suite** (`make test-summary`, 18 suites): `origin/master` + this change
  = 1454 assertions, 0 failed, on Bash 5.3 and on Bash 3.2 (`PATH=/bin:…`).
  New suite `tests/test_home_edge_cases.sh`: 16 assertions; before the fixes
  1 + 2 + 6 of its assertions failed (fixes 1, 2, 3) on the matching scenarios.
- **`make lint`, `scripts/check-i18n.sh` (122 keys), `scripts/check-conf.sh`**: pass.
- **Cost of the size estimate** (`--report-only --quiet`, empty `HOME`, stub
  `tmutil`, Apple Silicon, other jobs running): **0.36 s** with
  `TM_EXCLUSIONS_SKIP_DU=1`, **130 s** without. The 130 s is `du -sk` on the
  system-wide static rules that exist on a developer Mac
  (`/Library/Developer/CoreSimulator`, `/opt/homebrew/Cellar`, `Caskroom`,
  `/private/var/folders`), not the scan. This is the one place where the CLI
  itself is slow; see "To discuss".
