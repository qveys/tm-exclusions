tm-exclusions

Des sauvegardes Time Machine qui ne contiennent que ce qui compte : l’outil écarte automatiquement les caches, dépendances et artefacts de compilation qu’un développeur peut régénérer, et protège explicitement les données uniques.

Le problème résolu

Sur un Mac de développeur, une part importante de l’espace sauvegardé n’a aucune valeur : dossiers node_modules, environnements virtuels Python, caches de compilateurs, données dérivées de Xcode, modèles téléchargés… Tout cela se retélécharge ou se reconstruit. Le sauvegarder ralentit Time Machine, remplit le disque de sauvegarde et noie les fichiers réellement importants.

Exclure ces dossiers à la main est fastidieux et risqué : ils réapparaissent dans chaque nouveau projet, et une exclusion trop large peut faire perdre des données uniques (machines virtuelles, bases de données locales, sessions d’outils). tm-exclusions automatise ce tri de façon prévisible, réversible et vérifiable.

Architecture

Un script unique, organisé en étapes successives. Les règles sont décrites dans des fichiers texte simples au format type|cible|raison ; le code ne contient aucune liste de chemins en dur.

  • Configuration fusionnée : catalogue fourni avec l’outil, puis règles personnelles, puis fichier additionnel facultatif. Les préférences suivent la règle « la dernière valeur l’emporte », les règles s’additionnent, et une protection l’emporte toujours.
  • Cinq types de règles : path (chemin précis), pattern (nom de dossier recherché dans le dossier personnel), prune (zone dont les résultats de scan sont ignorés), keep (protection) et setting (préférence).
  • Scan en deux phases : collecte de toutes les correspondances, puis tri et traitement, pour un résultat déterministe et un affichage regroupé.
  • Double stratégie d’exclusion : exclusion attachée au dossier pour les chemins utilisateur, exclusion par chemin fixe avec élévation de privilèges pour les chemins système.

Choix techniques et pourquoi

Bash 3.2, sans dépendance

C’est le shell livré avec macOS : l’outil fonctionne sur une machine neuve, sans rien installer. Contrepartie assumée : aucune fonctionnalité de Bash 4 (tableaux associatifs, etc.).

Configuration plutôt que code

Ajouter un écosystème revient à ajouter une ligne commentée. Un validateur de syntaxe dédié vérifie les fichiers de règles en intégration continue.

Prudence par défaut

Les dossiers mixtes (données Docker, machines virtuelles, archives, sessions d’agents) sont livrés désactivés : l’utilisateur doit les activer explicitement.

Couche d’abstraction de tmutil

Trois fonctions encapsulent tous les appels à Time Machine. Hors macOS, elles simulent le comportement : la suite de tests tourne sous Linux sans toucher à aucune sauvegarde.

Échec explicite

Un statut d’exclusion inconnu n’autorise jamais d’ajout ni de retrait. Toute erreur, scan incomplet ou conflit de protection produit un code de sortie non nul.

Bilingue français / anglais

Les messages vivent dans des tables de traduction séparées, dont la parité des clés est contrôlée automatiquement.

Compétences démontrées

  • Scripting shell robuste et portable : mode strict, guillemets systématiques, gestion des signaux et nettoyage des fichiers temporaires, analyse statique ShellCheck.
  • Conception orientée sécurité des données : protections prioritaires, résolution des liens symboliques, refus des chemins ambigus, rapports traçables jusqu’à la ligne de configuration source.
  • Tests automatisés : plusieurs suites (comportement de bout en bout, sécurité, logique de publication, validateurs, catégories) exécutées à chaque modification.
  • Intégration et livraison continues : GitHub Actions avec actions épinglées par SHA, revue des dépendances, publication de versions et mise à jour automatique d’une formule Homebrew.
  • Outillage et qualité du dépôt : hooks Git imposant des messages de commit conventionnels, étiquetage et tri automatiques des tickets, journal des modifications tenu à jour.
  • Expérience utilisateur en terminal : affichage regroupé, barres de progression, couleurs désactivées automatiquement hors terminal interactif, mode silencieux pour l’exécution planifiée.

Le gain d’espace dépend de chaque machine et n’est pas chiffré ici.

Limites connues

  • Réservé à macOS : ailleurs, les opérations sont seulement simulées.
  • Le scan dynamique est volontairement limité à une profondeur de 6 dossiers ; les zones ignorées filtrent les résultats mais ne raccourcissent pas le parcours.
  • Les tailles affichées sont des estimations d’occupation disque, pas une garantie d’économie de sauvegarde (liens physiques, clones APFS).
  • Une protection ajoutée après coup ne supprime pas une exclusion existante : le conflit est signalé et doit être levé manuellement.
  • Les chemins système exigent des droits administrateur ; sans eux, ils sont comptés comme bloqués et l’exécution se termine en erreur.
  • La plupart des exclusions n’apparaissent pas dans les Réglages Système ; on les vérifie en ligne de commande.
  • La découverte d’images disque est désactivée par défaut et plafonnée à 50 éléments par exécution.
